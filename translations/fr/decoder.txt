@31 Chercher une clé que TypeScript ne peut pas vérifier

@34 Une variable est lue avant d’avoir une valeur

@37 Une propriété de classe ne reçoit jamais de valeur
@38 Avec les vérifications strictes, chaque propriété de classe doit être définie dans sa déclaration ou dans le constructeur.
@39 Donne-lui une valeur par défaut, définis-la dans le constructeur, ou rends-la facultative.

@41 `satisfies` vérifie une valeur par rapport à un type sans changer son propre type. Celle-ci ne correspond pas.

@43 Un argument de type ne respecte pas une exigence

@73 Un nom n’existe pas (encore)
@74 Le compilateur est tombé sur un nom qu’il n’a jamais vu. C’est en général une faute de frappe, une variable utilisée avant sa déclaration ou un import manquant.
@75 Vérifie l’orthographe, puis vérifie que le nom est déclaré avant cette ligne et dans la même portée.
@76 null dans un emplacement qui ne peut pas le contenir
@77 Avec la vérification stricte des nuls, `null` est un type à part entière et ne devient pas discrètement une chaîne ou un nombre.

@79 Une valeur est arrivée à un endroit qui n’accepte rien
@80 Un emplacement `never` veut dire « aucune valeur ne devrait arriver ici ». Cela suit souvent une vérification exhaustive qui a un cas de trop.

@82 Un type là où un autre type était attendu

@88 Cette propriété ou méthode n’existe pas sur ce type
